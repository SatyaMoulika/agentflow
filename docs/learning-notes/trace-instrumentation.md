# Phase 9A: tracing instrumentation foundation

AgentFlow marks inbound HTTP requests, synchronous workflow node execution, pure-node execution, Groq requests, calculator calls, authorized HTTP calls and agent tool steps with OpenTelemetry spans. Parent context follows normal in-process calls, including the FastAPI threadpool. Export remains disabled by default; the optional local exporter is described below.

The instrumentation emits only fixed, code-owned span names. It passes no workflow inputs or outputs, prompts, responses, node identifiers, endpoint URLs, headers, credentials or exception text to the tracing API. An exception escaping an instrumented function sets an error status without recording the exception; errors handled inside that function are not necessarily represented by an error status. Request error responses may be handled by the HTTP middleware, so their span status alone is not an HTTP outcome. Normal persisted run events and HTTP logs remain the source of truth for outcomes.

Instrumentation failures while creating, ending or setting the status of a span do not change application results. No request body is buffered by this instrumentation. LangSmith's implicit export remains disabled for agent execution.

The dispatcher, recovery discovery and worker delivery also have fixed-name spans. Migration `0013` adds a nullable W3C `traceparent` to the durable workflow dispatch record: the API stores the current trace context when creating a background run, and dispatcher and worker recover it from PostgreSQL. Broker messages retain only their opaque outbox ID. Later recovery deliveries use the original context. Baggage, vendor trace state and business data are not persisted in this field. Old records without context still run.

Export is disabled by default. Set `AGENTFLOW_TRACE_EXPORT_ENABLED=true` in each process to opt in to OTLP/HTTP at `http://127.0.0.1:6006/v1/traces`, for a locally running Phoenix collector. The exporter uses a bounded queue, a short timeout and no environment proxies; collector failure does not change execution. The sampler follows the parent decision and otherwise samples new traces. Only a fixed `service.name` resource is included. The collector must be managed separately and protected as telemetry data. Export is limited to localhost; remote collection and configurable sampling remain future work. A worker delivery that catches an error internally may finish with a successful span status; persisted events remain the source of truth.
